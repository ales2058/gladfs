# GladFS — учебная файловая система

Реализация файловой системы с таблицей размещения файлов (FAT) в файле-образе.
Проект выполнен на C++17 без сторонних библиотек и состоит из четырёх слоёв,
как и любая настоящая ФС.

## 1. Архитектура

| Слой | Файл | Назначение |
|---|---|---|
| Носитель | `src/blockdevice.*` | Образ `disk.img`. Единственные операции — «прочитать блок №N» и «записать блок №N» (прямое обращение к нужному месту на диске через fseek) |
| Размещение | `src/gladfs.*` | FAT: какие блоки заняты, какому файлу принадлежат и какой блок следующий |
| Метаданные | `src/gladfs.*` | Корневой каталог: записи по 64 байта с именем, размером, датами, счётчиком обращений, атрибутами, владельцем и правами |
| Интерфейс | `src/shell.cpp` | Интерактивная оболочка `fs>` с командами и контролем ошибок |
| Криптография | `src/crypto.*` | Шифр XTEA, режим CTR, вывод ключа из пароля (KDF), самопроверка по официальным тест-векторам |

Все числовые параметры собраны в `src/constants.h` — «волшебных чисел» в коде нет.

## 2. Раскладка образа (2048 блоков по 512 байт = 1 МиБ)

```
Блок 0        Суперблок: сигнатура "GLADFS1", версия формата (2), геометрия,
              счётчики, настройки шифрования (соль, контрольный блок)
Блоки 1..8    FAT — 2048 записей uint16_t (по одной на каждый блок):
                0x0000 (FREE)     блок свободен
                0xFFFE (RESERVED) служебный блок (суперблок, FAT, каталог)
                0xFFFF (EOF)      последний блок цепочки файла
                иначе              номер СЛЕДУЮЩЕГО блока этого файла
Блоки 9..24   Корневой каталог: 128 записей DirEntry по 64 байта (фиксированный,
              как корень FAT12/16)
Блоки 25..    Данные файлов и ПОДКАТАЛОГОВ (2023 блока): подкаталог — файл
              с атрибутом DIRECTORY, содержимое которого — такие же записи
              DirEntry (как в FAT32/UNIX), и он растёт как обычный файл
```

**FAT — это односвязный список блоков.** Поле `FAT[i]` играет роль `next`:
файл — цепочка «каталог → первый блок → FAT[first] → … → EOF». Та же идея,
что у односвязного списка из лабораторной №1, но хранится на диске и потому
переживает выключение питания.

## 3. Запись каталога (64 байта)

Три поля из постановки варианта №6 выделены курсивом.

| Поле | Размер | Комментарий |
|---|---|---|
| *имя файла* | 24 б | до 23 символов + '\0' |
| атрибуты | 1 б | биты: только чтение / скрытый / системный / в корзине |
| флаги | 1 б | запись занята |
| первый блок | 2 б | начало цепочки в FAT |
| *размер* — размер файла | 4 б | байт |
| *количество обращений* | 4 б | растёт при каждом чтении (cat, export) |
| *дата создания* | 6 б | структура Date (день, месяц, год) |
| дата изменения | 6 б | обновляется при записи |
| дата последнего обращения | 6 б | обновляется при чтении |
| nonce | 4 б | соль шифрования этого файла (CTR-режим) |
| владелец | 1 б | идентификатор пользователя |
| права | 1 б | rwx владельца (старший полубайт) и остальных (младший) |
| контрольная сумма | 4 б | CRC32 содержимого — защита от подмены/повреждения данных |

## 4. Шифрование (XTEA-CTR)

Классические проблемы FAT не включают шифрования — здесь оно есть:

- **Шифр**: XTEA (блок 64 бита, ключ 128 бит, 32 раунда) — учебная классика;
  корректность подтверждена официальными тест-векторами mbed TLS
  (команда `debug crypto`).
- **Режим**: CTR — гамма для каждого 512-байтного блока файла вычисляется
  как XTEA(nonce_файла, номер_блока). CTR позволяет шифровать блоки независимо,
  что и нужно блочной ФС (случайный доступ к любому блоку).
- **Ключ**: выводится из пароля тома функцией deriveKey (соль из суперблока,
  цепочка на XTEA, 2048 итераций). Сам пароль и ключ на диске не хранятся.
- **Проверка пароля** при монтировании: в суперблоке лежит контрольный блок
  verifier = XTEA_ключ(«GladFS!») — по нему сверяется введённый пароль.
- Пустой пароль при format — том без шифрования.
- `hexdump` показывает шифротекст «как есть», `cat` расшифровывает на лету.

## 5. Пользователи и права

В FAT нет ни пользователей, ни прав — здесь есть:

- Таблица пользователей хранится в **скрытом системном файле `_users` внутри
  самой файловой системы** (64 байта на запись: имя, соль, хеш пароля, uid,
  признак администратора). Файл защищён атрибутом «системный»: его нельзя
  прочитать, удалить или переименовать обычными командами.
- Пароли не хранятся: только соль и хеш (та же KDF на XTEA, 1024 итерации).
- Вход при монтировании: имя + пароль, 3 попытки. По умолчанию `root`.
- Права файла: `rwx` для владельца и `rwx` для остальных, как chmod
  (новый файл — `rw-r--`). Чтение требует `r`, запись и удаление — `w`,
  смена метаданных (mv, attr, chmod) — владелец или администратор.
- `root` — администратор: обходит проверки прав, управляет пользователями
  (adduser, passwd, chown).

## 6. Каталоги и пути

- Подкаталог — **файл с атрибутом DIRECTORY**, содержимое которого — массив
  64-байтных записей (тех же DirEntry). Формат на диске при этом НЕ изменился:
  каталоги появились без изменения раскладки.
- Корневой каталог фиксирован (128 записей, отдельная область диска), подкаталоги
  растут как файлы — до ~16000 записей каждый.
- Пути: «docs/2026/x.txt», «/docs», «..»; у оболочки есть текущий каталог
  (cd/pwd), права на создание/удаление внутри каталога проверяются по правам
  каталога-родителя (как в Unix).
- Содержимое подкаталогов шифруется как обычные данные — на диске не видно
  даже имён файлов внутри.
- fsck проверяет всё дерево: потерянные блоки, «склейки» цепочек, контрольные
  суммы, циклы каталогов и превышение глубины; восстановление двухпроходное.

## 7. Целостность данных (защита от подмены)

Ещё одна классическая беда FAT: правка байтов содержимого файла на носителе
проходит бесследно — ФС не проверяет данные. В GladFS у каждого файла в записи
каталога хранится **CRC32 содержимого**:

- сумма считается по открытому тексту при записи, поэтому ловит и прямую
  правку данных, и правку шифротекста (расшифрованный мусор даст другую сумму —
  это закрывает и «малябиальность» режима CTR);
- каждое чтение (cat, export, чтение таблицы пользователей) сверяет сумму;
  при несовпадении — отказ: «данные подменены или повреждены»;
- `fsck` проверяет суммы всех файлов и сообщает о несовпадениях; восстановить
  содержимое по сумме нельзя — она обновляется только при новой записи файла;
- самопроверка CRC32 (`debug crypto`) прогоняет известный вектор.

## 8. Корзина и безопасное удаление

В FAT удаление мгновенное и случайное — здесь двухступенчатое:

- `rm файл` — файл **перемещается в корзину**: помечается атрибутом TRASHED,
  цепочка FAT и данные не трогаются, поэтому восстановление мгновенно.
- `restore файл` — возврат из корзины (с контролем занятости имени).
- `purge` — очистка корзины **с затиранием данных нулями** (только админ).
- `rm -f` — удалить мимо корзины без затирания; `rm -w` — сразу с затиранием
  нулями (безвозвратно).

## 10. Сборка и запуск

Нужен компилятор g++ (MinGW-w64). Компилятор уже распакован в `D:\mingw64\mingw64\bin`
(в PATH его можно добавить, но не обязательно: `build.bat` найдёт его сам).

```
build.bat        → gladfs.exe
gladfs.exe       → работа с образом disk.img
```

Ручная сборка:
```
g++ -std=c++17 -O2 -Wall -Wextra -o gladfs.exe src\main.cpp src\blockdevice.cpp src\crypto.cpp src\gladfs.cpp src\shell.cpp
```

Сборка проходит без единого предупреждения (`-Wall -Wextra`).

## 11. Гарантии целостности и порядок записи

При каждой операции данные записываются на диск раньше метаданных, метаданные
(FAT + каталог + суперблок) — одной точкой фиксации. Если процесс оборвётся
после записи данных, но до фиксации, останутся «потерянные» блоки — `fsck`
их находит и возвращает в свободные (как chkdsk/ScanDisk в реальных ФС).

`fsck --repair` исправляет: потерянные блоки, циклы и битые ссылки в цепочках
(цепочка обрезается, размер усекается — данные спасаются до места повреждения),
блок, принадлежащий двум файлам, несоответствие размера и цепочки, счётчики
суперблока, неподписанные служебные блоки. Восстановление двухпроходное: сначала
fsck собирает, какие блоки реально нужны файлам, и только потом освобождает
лишнее — поэтому при «склейке» цепочек двух файлов ни один нужный блок
не освобождается. Контрольные суммы содержимого проверяются и сообщаются
о несовпадениях (само содержимое по сумме восстановить нельзя). Работает
и на зашифрованном томе: структуры ФС не шифруются, шифруются только данные.

## 12. Сознательные упрощения 

- Перенос mv между каталогами выполняется двумя фазами (удаление, затем
  добавление) и не атомарен: при сбое между фазами запись теряется, а блоки
  возвращает fsck; переносы между вложенными друг в друга каталогами запрещены.
- FAT хранится в одной копии (в настоящей FAT их две — FAT1/FAT2).
- ГПСЧ для солей/nonce учебный (time/clock); в настоящей системе — системный
  криптостойкий источник (BCryptGenRandom / getrandom).
- XTEA — учебная классика с 64-битным блоком; для реальных данных берут
  AES-256 (и аппаратное ускорение AES-NI).
- Права двухуровневые (владелец/остальные), без групп; бит `x` хранится,
  но не проверяется — исполняемых файлов в учебной ФС нет.
- Если таблица пользователей повреждена до нечитаемости, том пересоздаёт её
  с root без пароля — компромисс между безопасностью и доступностью данных.
- Нет журналирования (как journal в NTFS/ext4): при сбое консистентность
  восстанавливает fsck постфактум.
- Little-endian: образ привязан к порядку байт x86; переносимый формат
  потребовал бы явной сериализации полей.
- Имена: латиница, цифры и `. _ - + ~`, до 23 символов.
